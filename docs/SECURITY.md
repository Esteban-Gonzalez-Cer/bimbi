# Bimbi security and privacy

- No secrets, private keystores, OAuth refresh tokens, account exports, full routes or personal health records in Git. Local configuration is ignored.
- Firebase user probe and profile paths require matching UID and verified email. Rules validate the probe fields and size, the profile name, and custom avatar metadata. Client access to server payment attempts and entitlements is denied.
- Avatar writes also require the server-managed `bimbiAuthOrigin` claim and a password sign-in. Profile downloads use authenticated SDK calls, and cached images reside in app-private storage. The photo picker recompresses images and discards source metadata.
- The server accepts only known plan IDs and prices, validates auth and ownership, rejects live Stripe mode and unexpected currency/amount. Provider client secrets are returned only to the owner and not logged.
- Logs intentionally exclude SDK error bodies and request payloads. Only native alarm timing and generic statuses are retained as evidence. Use personal-free test screenshots.
- Android location is foreground-only; no background location permission. No Accessibility-service workaround.
- Usage Access and Display over other apps are opt-in and only requested from the Focus shield screen. App labels, icons, minutes, chosen apps and limits stay on the device (native app-private storage and the Flutter UI); none are written to Firebase or logs. The app list uses launcher `<queries>`, not `QUERY_ALL_PACKAGES`. Settings, the dialer, launchers and the keyboard are never covered (ADR-009).
- Sleep and Focus rules allow only the verified owner. Sleep rows are self-reported (`source == 'diary'`), keyed by date, with wake after bed, at most 16 h in bed, a note of up to 280 characters and no other fields, so no stages or scores. Focus rows allow 60 s–8 h, `completed` or `ended`, and an optional label of up to 40 characters. No points or rewards fields exist.
- Alarm safe dismissal is native, independent of Firebase/Flutter. Exact access and notification consent are checked before scheduling. Notification access is checked again at delivery and before playback; an active alert checks it every second and stops playback and recurrence if access is removed. Full-screen denial remains a visible degraded capability with notification dismissal when notifications are allowed.
- The only cloud environment used in this phase is an isolated development project. Production environments, production App Check/Crashlytics and release signing are not configured.
- Dependency review: package lockfiles are committed. Development-only Firebase emulator tools may have transitive advisories; see evidence. Never expose emulators to the internet or reuse their demo project identity in production.
